# Loop Engineering — 迭代优化

基于stackwich的Loop层："循环工作在/loop上运行，失败循环最多2次，从不静默。"

## 核心理念

**有上限的迭代，从不静默失败。**

## 四阶段循环

```
任务定义 → 执行 → 自我反思 → 质量门控
    ↑                              ↓
    └──── 失败时最多循环2次 ←──────┘
```

### 阶段1：任务定义

```yaml
目标: 明确要优化什么
基线: 当前版本的质量评估
标准: 什么算"完成"
最大迭代: 2次（共3轮）
```

### 阶段2：执行

- 按计划执行改动
- 记录每次改动的内容和原因

### 阶段3：自我反思

每次执行后检查：

| 维度 | 检查项 |
|------|--------|
| 完整性 | 是否覆盖了所有要求？ |
| 正确性 | 有没有错误或遗漏？ |
| 质量 | 是否达到预期标准？ |
| 改进 | 有什么可以优化的？ |

### 阶段4：质量门控

```yaml
通过条件:
  - 所有检查项通过
  - 无明显错误
  - 达到质量标准

失败处理:
  - 第1次失败: 列出问题，回到执行
  - 第2次失败: 列出问题，升级到human
  - 从不静默失败
```

## 失败循环上限

| 迭代次数 | 处理 |
|---------|------|
| 第1轮 | 正常执行 |
| 第2轮 | 修复第1轮的问题 |
| 第3轮 | 最后尝试，必须成功或升级 |
| 第4轮 | ❌ 禁止，必须升级到human |

**核心原则：最多2次重试（共3轮），从不静默。**

## 四种改进模式

### 1. 渐进精炼
```
V1 → V2 → V3 → 完成
每次小改进，逐步逼近目标
```

### 2. 试错修正
```
尝试A → 失败 → 分析原因 → 尝试B → 成功
快速试错，从失败中学习
```

### 3. 对比择优
```
方案A + 方案B + 方案C → 选最优
并行生成多个版本，选最好的
```

### 4. 反馈驱动
```
输出 → 收集反馈 → 改进 → 再输出
基于外部反馈迭代
```


## 超限终止

当达到最大迭代次数时：

1. 停止迭代
2. 输出当前最佳版本
3. 列出未解决的问题
4. 升级到human决策

## 与其他Skill的协作

- **prompt-engineering** — 提供高质量的初始prompt
- **context-engineering** — 管理迭代过程中的上下文
- **harness-engineering** — 编排迭代中的工具使用
- **graph-engineering** — 多Agent协作时的迭代

## 自我反思的真相⭐ 第九轮学习新增

> 来源：Huang et al. (2310.01798) + CRITIC框架 (2305.11738)

**关键发现：纯LLM自我反思无法纠正推理错误，必须借助外部验证。**

| 反思方式 | 效果 |
|---------|------|
| 纯自查清单 | ❌ 低效（LLM不知道自己错了） |
| 外部工具验证 | ✅ 有效（测试/搜索/代码执行） |
| Self-Consistency投票 | ✅ 推理任务提升17.9% |

### 有效反思模板

```yaml
反思步骤:
1. 用外部工具验证当前输出（运行测试、搜索事实、执行代码）
2. 对比验证结果与预期
3. 如果不一致，列出具体差异
4. 生成修正方案
5. 再次验证
```

### 7类失败模式（F1-F7）

| 编号 | 类型 | 示例 | 应对策略 |
|------|------|------|---------|
| F1 | 理解错误 | 误解用户意图 | 回到Prompt层重新分析 |
| F2 | 信息不足 | 缺少关键上下文 | 回到Context层补充信息 |
| F3 | 工具失败 | 命令执行错误 | 换工具或修复参数 |
| F4 | 逻辑错误 | 推理链断裂 | 重新推理或换路径 |
| F5 | 格式错误 | 输出不符合要求 | 按格式模板修正 |
| F6 | 范围越界 | 做了计划外的事 | 回到原计划 |
| F7 | 质量不达标 | 内容不够好 | 用PRM逐步检查 |

### 收敛判据：Delta评分法

```yaml
收敛条件:
  - 当前评分与上轮评分差值 < 0.5分（满分10分）
  - 连续2轮评分差值都 < 0.5分
  - 无新的失败模式出现

停止条件:
  - 达到最大迭代次数（2次重试）
  - 出现F1/F4类失败（需要回到上游层）
```

## 质量追踪向量⭐ 第九轮学习新增

每轮迭代记录多维度质量向量：

```yaml
iteration: 1
scores:
  completeness: 7/10    # 完整性
  correctness: 8/10     # 正确性
  format: 6/10          # 格式
  relevance: 9/10       # 相关性
total: 7.5/10
delta: 0               # 与上轮差值
failure_types: [F5]    # 失败模式
next_action: "修正格式"
```

## Reflexion框架集成⭐ 第五轮学习新增

> 来源：Shinn et al. 2023 — verbal reinforcement learning

**失败后用自然语言反思存入长期记忆，下次自动规避。**

```yaml
reflexion_flow:
  1_execute: "执行任务"
  2_evaluate: "环境/verifier给出反馈"
  3_reflect: "用自然语言总结：做错了什么、为什么错、下次怎么避免"
  4_store: "存入memory(type: workflow)"
  5_retry: "下次自动检索相关反思"
```

在Hermes中：
```python
# 反思后存储
memory_save(content="在XX任务中，YY策略失败，原因是ZZ，下次应该用WW", type="workflow")

# 下次执行前检索
memory_recall(query="XX任务 策略 失败")
```

## PRM过程奖励集成⭐ 第五轮学习新增

**步骤级评估优于结果级评估。**

每轮迭代不仅检查最终结果，也检查中间步骤：

| 检查点 | 评估内容 |
|--------|---------|
| 步骤1完成 | 输入→输出是否正确？ |
| 步骤2完成 | 是否符合预期？ |
| 最终结果 | 整体质量如何？ |

## Pitfalls

1. **不要无限迭代** — 最多2次重试
2. **不要静默失败** — 每次失败都必须报告
3. **不要跳过反思** — 每轮都要自我检查
4. **不要降低标准** — 质量标准不能因迭代次数多而降低
5. **不要重复同样的错误** — 每次迭代必须有改进
